# Face cluster accuracy and size

## Question

Does PicOrg cap face-cluster membership, and what should be measured to reduce duplicate-person groups or mixed-person clusters?

## Findings

- [S1][S2] There is **no hard maximum cluster size**. `FACE_CLUSTER_MAX_REPRESENTATIVES=12` caps only the shortlist used to find candidate clusters. With strict mode on, the implementation still checks a candidate against every member and keeps adding members as long as they pass. A cluster can therefore grow without a configured member limit. The `>100` run warning and UI purity acknowledgement are review safeguards, not size limits.
- [S1][S2] Current production clustering is intentionally conservative: cosine similarity must be at least 0.90 against every member. This reduces bridge merges but can split the same person into several groups when pose, crop, lighting, expression, or image quality varies. The default greedy assignment pass is input-order dependent.
- [S3] The service is currently reading a **2026-09-16 audit**, not a newly rebuilt report. It has 19,410 generic embedded faces and 1,734 generic clusters; the combined identity-first report has 1,837 cluster IDs. Its largest group has 106 rows. Coverage is incomplete: 10,321 selected inputs had no detected face, 2,514 were deferred for multiple faces, 2,326 were low quality, and four had read errors. These are audit counts, not measured cluster accuracy.
- [S3][S4] No source path appears in more than one group in this report. The identity-first groups are generated by matched identity and are not face-similarity clusters. For generic `face-*` groups, there is no human identity label in the audit proving that two separate groups depict the same person. So repeated-looking people across groups are plausible fragmentation, but this report alone cannot confirm it.
- [S10] The append-only image decision ledger had paths whose newest state superseded an older confirmation. Pair generation now uses the newest timestamp per path; ties follow ledger order.
- [S5][S6][S7][S9] The main accuracy gap is measurement on PicOrg's own confirmed images. A stronger encoder or a quality score may help, but neither justifies lowering the current floor without image-disjoint evaluation. Public benchmark results and quality models do not supply a threshold for this dataset.
- [S5][S8] HDBSCAN is worth a report-only comparison because it can leave weak members as noise and expose cluster persistence. It should not replace exact pair checks or approve moves: density-based grouping has its own bridge behavior and is not an identity verifier.

## Recommendation

Keep the 0.90 floor and avoid an arbitrary member cap. For cached review samples up to 1,200 embeddings, `--strategy complete_link` provides deterministic agglomerative complete-link; larger runs retain the existing default to bound quadratic memory. Pair generation now excludes superseded image labels. The current labeled sample shows a small precision gain but lower recall with complete-link, so the option is a tradeoff rather than a proven overall accuracy improvement. Do not switch the full service rebuild to the new strategy until an image-disjoint holdout and storage recovery make that run practical. Confidence: **medium**.

### Exploratory replay (2026-09-28)

Used cached dlib embeddings from 2026-09-01 and latest decisions per path, deduplicating superseded labels. After the identity correction and decisions written during this session, the newest ledger state yielded 758 eligible paths across 40 labels; all eligible paths were included. No media was read or moved. A prior 500-image exploratory sample showed 1.88–2.44% pair-membership changes across four shuffled greedy inputs (2.06% mean), consistent with the greedy algorithm's order sensitivity.

Also compared a report-only, deterministic agglomerative complete-link pass over the same normalized cosine distances, merging only when the maximum cross-cluster distance stayed within the 0.90 similarity floor:

| Measure | Existing greedy pass | Deterministic complete-link |
|---|---:|---:|
| Clusters | 34 | 40 |
| Largest cluster | 101 | 100 |
| Clusters spanning multiple confirmed labels | 13 | 14 |
| Pairwise precision among co-clustered pairs | 0.989 | 0.991 |
| Same-label pair recall | 0.978 | 0.942 |
| Identities split across clusters | 8 | 10 |

Greedy versus complete-link elapsed time was 0.66s versus 0.58s on this sample. Complete-link is deterministic and subject to a 1,200-embedding guard because its pair-distance state is quadratic. These are **diagnostic measurements**, not production accuracy: labels were not independently re-adjudicated, and the repeated face examples in this convenience sample are not an image-disjoint holdout. The completed runs used only cached vectors and performed no media reads or moves.

## Open gaps

- The service audit is from 2026-09-16, and the embedding cache used here is from 2026-09-01; recent assignments have not been reflected in a new face report.
- Labels in the 758-image replay were not independently re-adjudicated and are not a held-out estimate of target-population performance.
- No HDBSCAN comparison or full face rebuild was run.
