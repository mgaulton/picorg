# Shared agent capabilities

Use the same repo capabilities from any client. If the task is unclear, check `docs/FEATURE_FUNCTION_MAP.md` first.

- Noisy shell, file, git, test, or log output: `cas-compress` MCP.
- Repo structure, callers, callers-of-callers, or blast radius: `gitnexus` MCP with `query`, `context`, and `impact`.
- Low-complexity subtasks and routing hints: `llm-route-dispatch` and `tools/llm_route_classify.py`.
- Prompt refinement and loopback iteration: `prompt-optimizer` MCP.
- Shared Cursor rules and `.cursorrules` mirroring from AI-Memory: `tools/ensure-cursor-global-rules.sh`.
- Shared skills mirroring across agents: `tools/ensure-agent-skills.sh`.
- Durable handoff state: `docs/agent-workbench/WORK.md`, `docs/agent-workbench/handoff.json`, and `tools/agent-workbench-export.sh`.

- Cross-repo active work pointer: `AI_MEMORY_ROOT/global/active_workbench.json`.

Cursor-specific rules, skill sync, and the rest of the fleet surface are documented in `docs/AGENT_HANDOFF_RULES.md` and `docs/MULTI_AGENT_ORCHESTRATOR.md`.

It was generated by [rtt](https://github.com/yttrium400/reducethemtokens) and contains every file's imports, function signatures, class hierarchies, and method lists in 0 tokens (100% smaller than the 5,024-token raw source).

**Do not load `.rtt/context.txt` whole** (often 100k+ tokens). Use it as a **lookup index** only: path-scoped `rg` on that file, or **`cas_read_file`** with **`focus_keywords`** and a small line window. Open source files only for implementation bodies you must edit.

Use the index as your first lookup step:

- Before reading any source file, check the index to see if it already answers your question (signatures, return types, parameters, class members, imports)
- Use it to identify which specific files are relevant before opening them - do not scan files speculatively to understand structure
- When asked where something is defined, which methods a class has, or what a function signature looks like, answer from the index directly

Only open a source file when you need implementation details the index does not contain: function bodies, logic, comments, or the actual code to edit.

The first line of `.rtt/context.txt` shows when it was generated and how many files it covers. If it looks outdated relative to recent changes, or if the file is missing entirely, tell the user to run `rtt update` before continuing.
